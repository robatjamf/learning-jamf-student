Part 1

The Jamf Pro API

Jamf Pro exposes a REST API that lets you control almost everything the dashboard can do — programmatically. Instead of clicking through the UI, you send HTTP requests and get data back as JSON.

Think of the API as a remote control for Jamf Pro. You send a command, Jamf acts on it, and sends you a response. Automated, repeatable, and fast.

💻 Your Script Postman / Python / curl
HTTP Request →
🔒 Auth Token Bearer token
→
⚙ Jamf Pro API api/v1/...
JSON Response ←
📊 Your Data devices, users, policies
GET

Read data. List all managed computers, get a device's details, fetch a policy.

POST

Create something new. Add a user, create a group, enroll a device.

PUT

Update something that already exists. Change a user's name or email.

DELETE

Remove something. Delete a device record or remove a group membership.

# Step 1: Get a bearer token
POST  https://yourjamf.jamfcloud.com/api/v1/auth/token
Authorization: Basic [base64 credentials]

# Step 2: List all managed computers
GET   https://yourjamf.jamfcloud.com/api/v1/computers-inventory
Authorization: Bearer [token]
Accept:        application/json

# Step 3: Update a user's display name
PUT   https://yourjamf.jamfcloud.com/api/v1/users/42
Content-Type: application/json
{ "username": "crown", "fullName": "Crown M." }

Every API call needs a bearer token for authentication — you get one by logging in via the API first. Tokens expire, so automation scripts refresh them automatically.

Part 2

Personas at Jamf Pro

A persona is a profile of the type of person who uses Jamf Pro — their role, their goals, and their pain points. Understanding personas helps you build the right features for the right people instead of guessing.

Jamf Pro serves very different kinds of users. Here are four that came up in the workshop:

👨‍💻

IT Administrator

The IT Admin

Manages hundreds of devices across the organisation. Needs to deploy, update, and secure devices at scale — fast.

Biggest Pain Point

"I spend half my day on manual tasks that should be automated."
👩‍💼

System Administrator

The Sys Admin

Focuses on policies, scripts, and configuration profiles. Needs precision — one wrong policy can affect every device.

Biggest Pain Point

"Testing changes on a live fleet is terrifying. I need a staging environment."
👨‍🏫

Education IT

The School Tech Lead

Deploying iPads and MacBooks to students and staff. Needs to set up devices fast at the start of each school year.

Biggest Pain Point

"We have 1,200 devices to configure and school starts in 3 days."
🛡

Security Engineer

The Security Lead

Cares about compliance, encryption, and who has access to what. Uses Jamf to enforce security policies across the fleet.

Biggest Pain Point

"I need to know every unencrypted device in the org — right now."

Putting It Together

How APIs serve each Persona

The API is not one-size-fits-all. Each persona uses it differently — or uses tools built on top of it to serve their specific needs.

Persona How They Use the Jamf API Key Endpoints
IT Admin Automates bulk device updates, runs nightly scripts to check compliance computers-inventory, policies, patch-management
Sys Admin Pushes configuration profiles via API, deploys scripts remotely scripts, configuration-profiles, commands
School Tech Lead Mass-enrolls student devices at term start via automated workflows mobile-devices, prestage-enrollments, departments
Security Lead Queries device compliance status, triggers remote lock or wipe if needed device-enrollments, mdm-commands, computer-management

This is why persona mapping matters before you build — the same API can serve completely different needs. Knowing who you are building for changes what you build and how you design it.
