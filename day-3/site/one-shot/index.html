Day 1 — Context, Empathy & Persona Mapping

What stood out from the icebreakers?
The introductions and backstories showed how differently our cultures process and relay information. The liquorice tasting was memorable — not everyone enjoyed it, but it got a lot of good laughs and made the room feel open.
What is Jamf?
Jamf is a company focused entirely on designing and deploying solutions that help customers manage and secure their Apple devices. What surprised me was how well it integrates with other software — it's not a replacement, it's a complement.
Persona mapped: Enterprise IT Admin
Her biggest pain point was being stuck doing work she wasn't supposed to — manually entering new hire data and rewriting scripts after every update. If I could build one thing for her, it would be an automated flow: HR feeds identity data into a system like ServiceNow or a SIEM, which then connects directly to Jamf Pro. No more manual entry, no more scripts lost after updates.
Biggest Takeaway

There are no wrong questions. It sounds simple, but it gave the whole group the confidence to actually participate. One brave question opens the door for everyone else.

Day 2 — APIs, VMs & Webhooks

What did you do with the VM?
Used Virtual Buddy to spin up a macOS virtual machine, enrolled it into a Jamf Pro instance, then logged in to view the device. We also set up a webhook that fired whenever a device attribute changed and sent the payload to a webhook testing site.
How would you explain "a computer inside a computer"?
To a tech-savvy friend: it shares the same hardware as the host. To a non-tech friend: it's like a model house inside your actual house — the model uses the space and storage of the real one.
What API calls did you make?
We sent POST requests through the Jamf Pro API to create new categories on the server. The API is like a restaurant — you're the client, the API is the waiter, and Jamf Pro is the kitchen. You send an order and get data back.
What did the webhook payload look like?
It came through as XML, which looks a lot like HTML. The device ID was clearly visible inside the payload. Seeing that structure made the difference between XML and JSON much more concrete.
What Clicked

How XML looks and how it differs from JSON. Seeing them both in context made it real.

What I Want to Explore

Hosting my own sites on a Linux VM in a way that other people can actually access them.
