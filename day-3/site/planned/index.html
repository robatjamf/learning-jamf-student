Day 1 — Jamf & MDM
Cultural exchange, device management, and persona mapping

Everyone got the same instructions — draw a duck. Every single duck came out different.

Why it matters Same task + same instructions = wildly different results. This is the core challenge in IT: when you deploy a policy or write a ticket, every person reading it builds a different mental model. Jamf Pro exists partly to eliminate that ambiguity — one configuration pushed from one place, identical on every device.

In AI work: this is why writing a detailed prompt with context gets you a better result than a short vague one. The AI draws exactly the duck you described.

Sarah shared how watching people on terminals in movies sparked her curiosity about tech — that moment of "what are they actually doing on that black screen?"

New tool discovered from the group: DIA — a browser AI that helps you understand complex tools or workflows while you're using them.

Pattern here Curiosity from a movie scene → 3-day deep dive into APIs, terminals, and AI agents. That's how most people in tech started: wondering "how does that work?"

Jamf makes it easier for organizations to manage and handle their Apple devices — from schools to multinational companies.

Surprising fact Some of Jamf's biggest customers don't want it publicly known they use Jamf (competitive advantage, security posture). Others wear it as a badge of honour. Same product, opposite PR strategies.

MDM = Mobile Device Management. One IT admin can push settings to 10,000 devices simultaneously instead of touching each one individually. Like a school principal broadcasting rules to every classroom at once.

Sarah's group mapped the Help Desk Technician persona. Here's what their day looks like:

  • 6 identical tickets with no way to batch-resolve them
  • iPad issue ticket arrives with no screenshot, no details
  • Multitasking across multiple open cases simultaneously
  • Resolves 8 tickets — 15 more arrive immediately
  • Some issues require Jamf Pro permissions they don't have
Sarah's build idea A tool that groups tickets automatically by device type and problem category — so technicians see patterns, batch similar issues, and stop context-switching between unrelated problems. This is exactly what Smart Groups in Jamf Pro do at the device layer.
Day 2 — APIs, VMs & Webhooks
Talking to servers, computers inside computers, and event-driven automation
API Flow — The Waiter Model
Webhook vs Polling

Claude Code is a command-line AI agent — it lives in your terminal, can read your files, write code, and run commands. You interact with it by typing, not clicking.

Setup sequence (in order) Install Node.js → Install Claude Code via curl → Set your ANTHROPIC_API_KEY → Run claude /init inside your project folder → Claude reads the repo and creates CLAUDE.md

CLAUDE.md is the briefing document Claude reads at the start of every session. It's how Claude "remembers" your project between conversations. The richer the CLAUDE.md, the smarter Claude starts.

A Virtual Machine is a computer running inside your computer. It has its own operating system and behaves like a totally separate machine.

Sarah's analogy (from her log) "A computer installed inside the actual machine that can be used to run code and scripts which might end up crashing the actual machine." That's exactly the point — crash the VM, not your real Mac.

A snapshot is a frozen save point. You take one before doing anything risky. If it all goes wrong, you restore the snapshot and it's like it never happened.

Tools used: VMware Fusion, Virtual Buddy, Tart (for Apple Silicon macOS VMs). IPSW = the macOS installer file.

Step 1: Authenticate (get a wristband) You POST your username+password to Jamf's API. Jamf sends back a Bearer Token — a long string of letters. You only do this once per session.
Step 2: Use the token (flash your wristband) Every command after that includes -H "Authorization: Bearer $TOKEN". Jamf checks and lets you through without re-entering your password.
Step 3: What jq does The API sends back raw JSON. Piping to | jq . pretty-prints it with colour and indentation so humans can read it.
REST verbs in everyday life GET = reading a menu. POST = placing an order. PUT = changing your order. DELETE = cancelling it. Every curl command you ran used one of these four.
XML vs JSON JSON uses curly braces: {"name":"Sarah"}. XML uses tags: <name>Sarah</name>. Same information, different wrapping. The Jamf Classic API uses XML; the newer API uses JSON. You used both on Day 2.

A webhook is a URL that receives data automatically when something happens. You don't ask for it — the server calls you.

The chain that happened on Day 2 You updated your Extension Attribute via API → Your computer joined the "Workshop Participants" Smart Group → Jamf fired a webhook → A JSON payload appeared live on webhook.site. All automatic. That's event-driven integration.

Sarah's analogy: "It's like Slack when you send a message and get that the person is away or some notification if the person is not available." The notification arrives when the event happens — you didn't have to keep checking.

Polling vs Webhook: Polling = "Are we there yet? Are we there yet?" Webhook = "I'll text you when we arrive."

Command Cheat Sheet
Click any command to copy it. Each one has a plain-English explanation.
What is curl? curl is a browser you control with text. Instead of clicking a URL in Chrome, you type a command. The server doesn't know the difference.
What does \ (backslash) mean? When a command is too long for one line, backslash says "this line isn't finished yet — keep reading the next one."
What does | jq . mean? The pipe | passes output from one command into the next. jq . formats messy JSON with colour and indentation.

Jamf Pro Authentication (Bearer Token)
Authenticate + save token to $TOKEN variable (do this first)
TOKEN=$(curl -s -u "jamfpro_api:eap.zog.neek26" \ -H "Content-Type: application/json" \ -X POST \ "https://projsadp.jamfcloud.com/api/v1/auth/token" \ | jq -r '.token')
Confirm your token was saved correctly
echo $TOKEN
Jamf Pro API Queries
List all computers in Jamf Pro
curl -s \ -H "Authorization: Bearer $TOKEN" \ "https://projsadp.jamfcloud.com/api/v1/computers-inventory" \ | jq .
Get a single device by its ID number
curl -s \ -H "Authorization: Bearer $TOKEN" \ "https://projsadp.jamfcloud.com/api/v1/computers-inventory/YOUR_DEVICE_ID" \ | jq .
Update Extension Attribute — triggers Smart Group + webhook!
curl -X PUT \ -H "Authorization: Bearer $TOKEN" \ -H "Content-Type: application/xml" \ "https://projsadp.jamfcloud.com/JSSResource/computers/id/YOUR_DEVICE_ID" \ -d '<computer> <extension_attributes> <extension_attribute> <id>1</id> <value>Sarah</value> </extension_attribute> </extension_attributes> </computer>'
Token Cleanup (Security Best Practice)
Invalidate your token when done — always do this
curl -X POST \ -H "Authorization: Bearer $TOKEN" \ "https://projsadp.jamfcloud.com/api/v1/auth/invalidate-token"

Compound Engineering Loop
The four-phase cycle that makes AI collaboration compound over time
1
Plan
80% of the real work. Define what you're building, surface risks, agree on approach. The plan IS the work. Execution is confirmation.
2
Work
Build it. Let the agent execute against the plan. Keep your plan visible so you can compare as things come together.
3
Review
Open the output and use it yourself first. Your judgment is the primary review tool. Then ask the agent to find gaps against the plan.
4
Compound
Distill decisions, dead ends, and reasoning into COMPOUND.md. The next session inherits everything instead of starting from zero.
7 Transferable Principles
The quality of your output is determined by the quality of your context. The agent doesn't know your mental model, your constraints, or what "done" looks like. Your job is to share that. Point it at relevant files, explain the why, share constraints upfront.
80% planning, 20% building. If you're mostly watching the agent write code, you skipped the important part. Ask it to explain its approach first, poke holes in the plan, iterate until confident.
The agent starts from zero every time. You've been thinking about this. The fastest path to good output: transfer your mental model directly. "Here's how I'm thinking about this..." "The most important thing is..."
Sunk cost is a trap. Warning signs: solution getting more complex, agent keeps switching approaches, something feels off. Starting fresh isn't failure — it's the skill.
This is collaboration, not delegation. You share context, the agent explores. The agent proposes, you refine. Ask questions: "What do you see?" "What could go wrong?" Let the agent ask you questions too.
Your eyes and judgment are the primary review tool. Open the output. Use it. Click the buttons. Read the content. The question isn't "is this good?" — it's "does this match what I planned?"
Every session is rich with context that disappears when you close it. Distill decisions, tradeoffs, dead ends, and reasoning into COMPOUND.md after every session. Future-you and future-Claude both inherit it.

What stood out from the icebreakers?
"The duck drawing exercise — it made me realise that as we work with different people at school or at work, people can have their own understanding. By the end of the activity people had their own different ducks. So as we all might get the same task and questions, people have their own understanding, imaginations and thinking."
Why this matters in IT This is the entire argument for why MDM tools like Jamf exist. A ticket that says "fix the Wi-Fi issue" means something different to every technician. A Jamf configuration profile removes that ambiguity — the same setting goes to every device identically. Same drawing instructions, same duck every time. And in AI: a vague prompt gets a generic answer; a detailed one gets exactly what you meant.

I also shared new tools I'm using that others might not know about. Day 1 — After Block 3
What were the biggest pain points for the Help Desk Technician persona?
"Having 6 similar tickets and unable to solve them all at once. Not enough information on the ticket he got for the iPad issue, no screenshot, no further information. Multitasking between two tickets. After working on 8 tickets, he got 15 more. Some of the issues he had to solve he didn't have permissions in Jamf Pro to work on them."
The permission gap is real That last pain point — no Jamf permissions — is a structural problem that Jamf admins have to design around. Role-Based Access Control (RBAC) in Jamf determines who can see and do what. The technician needed someone with higher privileges, but that creates a bottleneck. Automating with the API (as you did on Day 2) can bridge some of these gaps — when you have the right token, you have the right access.
Day 2 — After Block 2
How would you explain "a computer inside a computer"?
"A computer running inside another computer. It has its own operating system and behaves like a separate machine. Or — it's a computer that is installed inside the actual machine that can be used to run code and scripts which might end up crashing the actual machine."
This is exactly the use case That second explanation is the key insight: run risky things in the VM, not on your production Mac. This is how security researchers test malware, how developers test scripts before deploying them to real devices, and how Jamf admins test new configurations before pushing to 10,000 machines. Crash the snow globe, not the room.
Day 2 — After Block 4

That Slack analogy is spot on Slack's "away" notification is literally event-driven push. The server detected a status change and pushed a notification to you without you asking. That's identical to what Jamf did: device joined Smart Group → webhook fires → data appears at webhook.site. You built the same pattern in a real enterprise system without realising it.

This is the core insight of the Compound Engineering Loop Speed comes from clarity, not from rushing. Two principles in one sentence Context shapes what AI can do — garbage in, garbage out, but also gold in, gold out. Conversation means you can correct, redirect, and build iteratively. You're not submitting a form and waiting. You're collaborating with something that can ask you questions, catch your gaps, and improve with every exchange.
