Day 3

Claude Code + AI Agents

Day 3 was about learning to work with AI — not just use it. Claude Code is an agent: it doesn't just talk, it reads files, writes code, runs commands, and builds things for you.

The key shift: the quality of what the agent builds is determined by the quality of the context you give it. A vague prompt gets a vague result. A detailed plan gets a precise result.

The Core Loop

Compound Engineering

01

Plan

"Do I have enough context to build this?"

Define requirements, gather context, create specs. Before you touch the keyboard.

02

Work

"Am I staying within the plan?"

Execute with AI assistance. Stay inside the agreed plan — don't let it drift.

03

Review

"Does this match what I intended?"

You evaluate first. Open it, use it, compare to your plan. Then ask the agent for gaps.

04

Compound

"What should the next session inherit?"

Distill decisions, tradeoffs, dead ends — so future sessions start with full context.

What Each Phase Means

Phase Breakdown

Plan

Define what you're building. Gather context. Answer the agent's questions before it has to guess.

Try: "What questions do you have before we start?"

Work

Execute with Claude Code. Watch what it builds. Stop it if it drifts from the plan.

Try: "Explain back to me what we're trying to do" if something feels off.

Review

Open the output yourself first. Use it. Click buttons. Your judgment comes before the agent's.

Try: "Based on our plan, what did we miss?"

Compound

Run /compound at the end of the session. It distills everything — not just what you built, but why.

Like a pilot's logbook: route, weather decisions, turbulence, what you'd do differently.

The Shift

New Rules

01
Context is everything. The agent only knows what you tell it. A vague brief gets a vague build.
02
Planning > building. Before AI: planning was easy, coding was hard. Now: planning is hard, execution is trivial.
03
Share your mental model. The picture in your head of what "done" looks like — the agent doesn't have it automatically.
04
Review against your plan. Your eyes and judgment come first. Then ask the agent what it missed.
05
Recognize when to quit. Sunk cost is a trap. Starting fresh with better context is faster than pushing through a bad path.
06
It's a conversation. Not a command line. Back and forth. Refine. Improve. Iterate.
07
Compound your sessions. Distill the full session so the next one inherits everything.

Reference Notes

Key Concepts

Everything you learned, in plain English. Read these before a test or interview.

Day 1 — Core

What is Jamf Pro?

Jamf Pro is a device management platform exclusively built for Apple devices — Macs, iPhones, iPads. IT admins manage thousands of devices from a single dashboard without ever physically touching them.

You can install apps, push security policies, wipe a lost device, enforce passwords, and enroll new Macs — all remotely.

Why we use itCompanies with lots of Apple devices can't have IT manually configure each one. Jamf Pro makes it scalable — one admin can manage 10,000 devices as easily as 10.
Day 1 — Core

MDM vs DDM (Blueprints)

MDM is traditional: server sends a command, device receives it, confirms, and replies. Every action routes through Apple's push servers.

DDM (Blueprints) is newer: the server describes the desired state and the device figures out how to get there itself. Less back-and-forth, faster results.

Why it mattersDDM is faster and more reliable. The device works independently toward the goal without waiting for instructions one at a time.
Day 1 — Concept

Zero-Touch Enrollment

A device goes from factory box to fully configured — apps installed, policies applied, settings locked — without IT ever physically touching it.

The device connects to the internet, checks in with Apple, gets redirected to Jamf Pro, and configures itself using pre-built profiles.

Why it mattersA school district getting 500 new iPads doesn't need to configure each one. They ship straight to classrooms, students turn them on, they're ready.
Day 2 — Core

What is an API?

An API (Application Programming Interface) is a way for software to talk to other software. You send a request, you get data back.

Every time you check the weather app, it sends a request to a weather server using an API, and gets the forecast back. You never see it — it's in the background.

Why we use itJamf Pro has an API that lets you automate anything — create categories, enroll devices, query inventory — without clicking through the UI.
Day 2 — Core

HTTP Methods

HTTP methods are the actions you can take with an API:

GET — Read data. "Show me all devices."
POST — Create something new. "Add this category."
PUT — Update something existing. "Change this device's name."
DELETE — Remove something. "Delete this policy."

Why it mattersEvery API in the world uses these same four methods. Learn them once, understand any REST API — Jamf, Spotify, Stripe, anything.
Day 2 — Tool

What is Postman?

Postman is a tool for testing API calls — like a web browser, but for APIs instead of websites.

You type in the URL, pick a method (GET/POST/PUT/DELETE), add any data, and hit send. You see exactly what comes back from the server.

Why we use itSean used it to make a POST request and create a real category inside Jamf Pro — without writing a single line of code.
Day 2 — Core

What is JSON?

JSON is the standard format for sending data over the internet. Uses curly braces, keys, and values.

{"name": "Sean", "role": "developer"}

When you make an API request, the server usually sends back JSON. When you send data, you send it as JSON.

Why it mattersAlmost every modern app uses JSON to move data around. Read and write JSON, and you can work with any API.
Day 2 — Concept

Virtual Machines (VMs)

A virtual machine is a computer running inside another computer. It has its own OS and behaves exactly like a real, separate machine — but it's just software.

Sean ran a macOS VM using Tart on his MacBook, then enrolled it into Jamf Pro as if it were a real device.

Why we use themVMs let you test things safely. Break it, wipe it, start over — without affecting your real machine. IT teams test policies on VMs before pushing to real devices.
Day 2 — Concept

Webhooks: Push vs Pull

Pull (Polling) — Your system asks the server "anything new?" over and over on a schedule. Wasteful if nothing changes between checks.

Push (Webhook) — You give the server a URL. When something happens, the server sends data to you immediately.

Why it mattersWebhooks are used everywhere: payment confirmations, Slack notifications, GitHub alerts. Jamf uses them to notify the moment a device checks in or triggers an alert.
Day 3 — Core

What is an AI Agent?

An AI agent is not just a chatbot — it can actually do things. Read files, write code, run commands, build software.

Claude Code is an agent. When you describe what you want, it doesn't just answer — it opens your files, understands your project, and builds the thing.

Why it mattersKnowing how to give an agent the right context and direction — and how to review its work — is a skill that applies to every AI tool that exists today and will exist in 5 years.
Day 3 — Concept

Context & Prompting

Context is everything the agent knows about what you're trying to build. More relevant detail = better understanding.

Prompting is how you give it instructions. A weak prompt gets a generic result. A detailed prompt with constraints and examples gets something precise.

The key insight"Make me food" vs "Make me a grilled cheese with tomato on sourdough." Same tool. Completely different output. Quality in = quality out.
Day 2 — Concept

Bearer Tokens

A Bearer Token is a short-lived credential that proves you're authenticated. You log in once to get the token, then attach it to every API request instead of sending your password every time.

In Postman: Authorization: Bearer eyJhbGci...

Why it mattersStandard way to secure API access. Jamf Pro uses bearer tokens for its API. If a token is stolen, you revoke it without changing your password.
