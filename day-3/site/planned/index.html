Day 1 Debrief

What Jamf does
= MDM for Apple
Jamf is a mobile device management security platform that helps manage Apple devices. It lets organisations automate device deployment and configuration — from enterprises to schools.
Persona mapped
= Enterprise IT Admin
Biggest pain points: manually entering new hires, API scripting, and manually triaging tickets. The fix? Automation for all the repetitive manual work.
Cultural exchange
= duck + liquorice
Duck-drawing showed how different people solve the same problem. Tasted Dutch liquorice — zoet (sweet) and zout (salty). Shared about Figma and how AI trends got me into tech.
Day 1 takeaway
= depth over surface
"Getting to know in depth what Jamf is about." — Me, Day 1.

Day 2 Debrief

VM = two-headed body
= computer inside a computer
"Each head works independently but needs the same body to function." Running another machine's software on your local hardware — one body, two systems.
API = middleman
= frontend ↔ backend bridge
The API takes the order from the frontend, communicates with the database/server, and brings back the data. Like a waiter — you never go into the kitchen.
What I created
= POST request → Jamf
Used a POST request in Postman to create a category for my virtual machine in the Jamf Pro instance. Real API call, real result.
Webhooks
= event-driven data push
A way to send data to a URL when an event triggers it. The payload came back as JSON. Still wanted more clarity on the full picture going into Day 3.
Day 2 takeaway
= VMs are easier than expected
"How easy it is to install a VM into a machine. How Jamf also caters for virtual machines." — Me, Day 2.

Day 3 Debrief

One-Shot vs Planned
= free will vs full control
One-shot means giving Claude free will to do whatever it wants with the information. A planned build means having full control — every design, layout, color, and placement is up to you.
What surprised me
= specificity = power
The more specific your prompt, the more advantage you have over the outcome. Vague prompts get vague results. Detail gets you exactly what you envisioned.
What the plan unlocked
= intent → outcome
During planning I got to decide: what info to display, what colors, which topics were fuzzy, how I'd use the page, how many quiz questions. Every decision shaped the result.
What the agent caught
= partner, not just tool
Claude added extra accents to the theme, a quick reference section, and a tools table showing what I've explored vs what's still to discover. Things I hadn't thought to ask for.
Principle I'll remember
= context is everything
"Context is very important. Be specific, and write down every single detail you want." — Me, Day 3.
AI in one sentence
= unique tool, right context
"AI is a very unique, cool tool. When used correctly with the right context, you can create or even solve great things." — Me, Day 3.

Command Cheat Sheet

1. Authenticate + save token 
TOKEN=$(curl -s -u "jamfpro_api:eap.zog.neek26" \
  -H "Content-Type: application/json" \
  -X POST \
  "https://projsadp.jamfcloud.com/api/v1/auth/token" \
  | jq -r '.token')
2. List all computers (GET) 
curl -s \
  -H "Authorization: Bearer $TOKEN" \
  "https://projsadp.jamfcloud.com/api/v1/computers-inventory" \
  | jq .
3. Update Extension Attribute (PUT) — triggers webhook! 
curl -X PUT \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/xml" \
  "https://projsadp.jamfcloud.com/JSSResource/computers/id/YOUR_DEVICE_ID" \
  -d '<computer>
  <extension_attributes>
    <extension_attribute>
      <id>1</id>
      <value>YourName</value>
    </extension_attribute>
  </extension_attributes>
</computer>'
4. Invalidate token (security best practice) 
curl -X POST \
  -H "Authorization: Bearer $TOKEN" \
  "https://projsadp.jamfcloud.com/api/v1/auth/invalidate-token"

Quick Reference

Analogies Wall

API
= restaurant waiter
You tell the waiter what you want. The waiter tells the kitchen. The kitchen sends the food back. You never go into the kitchen.
Virtual Machine
= two-headed body
"Each head works independently but needs the same body to function." — Lucile, Day 2.
Webhook
= doorbell
You don't check the door every five minutes. The doorbell rings when someone arrives. Webhooks ring when events happen.
Bearer Token
= wristband at an event
Show your ID at the door once, get a wristband. Flash the wristband everywhere else without showing ID again.
Context (AI)
= stranger + directions
If you ask a stranger to grab your jacket, they need to know where you live, what it looks like, and where you left it. That's context.
Compounding
= pilot's logbook
After every flight, the pilot records the route, weather decisions, turbulence. The next pilot starts with all of that instead of figuring it out from scratch.
