Day 2

APIs, VMs & Webhooks

APIs

The iMessage Analogy

Like sending a text — you (client) send a message through iMessage (API) to the other user (server) and get a response (data) back.

Virtual Machines

A Computer Inside a Computer

An imitation you can experiment with safely — like a snow globe inside your room.

POST Request

Creating with the API

Made POST requests in Postman. Created a category and saw the name appear. Created an extension returning an ID.

Webhooks

Push vs Pull

Push = sending stuff. Pull = getting info from a server to your machine. Webhooks push data to you the moment something happens.

Key Concepts from Day 2

  • REST API — GET (read), POST (create), PUT (update), DELETE (remove)
  • Bearer Token — Like a wristband: show ID once at the door, flash it everywhere after
  • JSON — Structured data: {"name": "Shine", "role": "student"}
  • Polling vs Webhooks — "Are we there yet?" vs "I'll tell you when we arrive."

01

Context Is Everything

The quality of output = quality of context. The agent only knows what you tell it.

02

Planning > Building

80% planning, 20% building. The plan IS the work. Execution is confirmation.

03

Share Your Mental Model

The agent starts from zero every time. Transfer your picture of "done."

04

Recognize When to Quit

Sunk cost is a trap. Starting fresh with better context is faster than pushing through.

05

It's a Conversation

Not a command line. Collaboration, not delegation.

06

Review Against the Plan

Your eyes and judgment are the primary review tool. Evaluate yourself first.

07

Compound Your Sessions

Distill decisions, tradeoffs, and dead ends so every session starts smarter.

The Biggest Takeaway

Never be fixed to one solution. Whether it's drawing a duck, calling an API, or prompting an AI — the best outcomes come from thinking outside the box and building on what you learn each time.
