Day Summaries

Day 1 Context, Empathy & Persona Mapping

What is Jamf?

Jamf is a company focused entirely on designing and deploying solutions that help organisations manage and secure Apple devices. What was surprising: Jamf does not replace existing IT tools — it integrates with them. Identity providers, SIEM platforms, and ServiceNow all work alongside Jamf Pro rather than being displaced by it.

The Enterprise IT Admin Persona

The mapped persona was an Enterprise IT Admin. Her biggest pain points were tasks she was never meant to own: manually entering new hire information and rewriting scripts that got deleted after every system update.

The proposed solution: build an automated flow where HR data feeds into an Identity provider (which stores employee records and permissions), which then connects to a SIEM or ServiceNow, which in turn syncs with Jamf Pro. No manual entry, no lost scripts. The Identity layer is the key piece most organisations are missing.

Biggest Takeaway

There are no wrong questions. It sounds simple, but it gave the whole group the confidence to actually participate. One brave question opens the door for everyone else — and the answer to an "obvious" question is often exactly what someone else needed to hear.

Day 2 APIs, VMs & Webhooks

Virtual Machines

Used Virtual Buddy to spin up a macOS VM, enrolled it into a Jamf Pro instance, and logged in to view the device in the console. A VM shares the host machine's hardware (CPU, RAM, storage) — it does not get its own dedicated chips. Think of it like a model house inside your real house: the model uses space inside the actual structure.

The Jamf Pro API

Sent POST requests through the Jamf Pro REST API using curl. The request created new categories in the Jamf Pro instance. The API works like a restaurant: you are the client, the API is the waiter, and Jamf Pro is the kitchen. You send an order (request) and get data back (response).

Webhooks

Set up a webhook that fired whenever a device attribute changed in Jamf Pro. The payload arrived as XML — visually similar to HTML. The device ID was clearly visible in the payload structure. This made the difference between XML and JSON concrete: same concept, different syntax.

Push vs pull: pull means you ask for data on a schedule (polling). Push means the server sends data to you the moment something happens. Webhooks are push — more efficient for real-time events.

What Clicked

Seeing XML and JSON side by side. Understanding that they both encode structured data but look and read differently — and that the choice between them is often dictated by what the system supports, not personal preference.

Day 3 AI-Native Development

The Compound Engineering Loop

Day 3 introduced a structured approach to building with AI: Plan → Work → Review → Compound. The goal is not just to ship something quickly — it is to build something better each round by being intentional. Decisions, tradeoffs, and reasoning are captured in COMPOUND.md so each session builds on the last.

Two Files, Two Roles

CLAUDE.md — project setup, structure, and current state. Kept lean.

COMPOUND.md — rich session history: decisions, tradeoffs, dead ends, reasoning. This is where context accumulates over time.

Claude Code in the Terminal

Claude Code is a CLI tool that brings AI assistance directly into the development workflow. It reads your project context via CLAUDE.md, uses slash commands for common actions (/init, /compact, /clear), and can read, edit, and create files in your project without leaving the terminal.
