Cheat Sheet

Key commands and concepts — quick reference for Git, Tart, curl, and Claude Code.

Git

Git is a distributed version control system. It tracks changes to files over time and lets multiple people collaborate on the same codebase without overwriting each other's work.

Core Concepts

Repository (repo)

A folder tracked by Git. Contains your files and the full history of every change ever made. Can live locally on your machine and/or remotely (e.g. on GitHub).

Branch

An independent line of development. main is the default. You create a branch to work on a feature or fix without affecting the main codebase. Branches are cheap — create them freely.

Commit

A saved snapshot of your staged changes. Each commit has a unique ID (hash), a message, an author, and a timestamp. The commit history is your project's timeline.

Remote

A version of the repo hosted elsewhere (usually GitHub). origin is the conventional name for your primary remote. You push to share your changes; you pull to receive others'.

Staging Area (Index)

A preparation zone. Files you git add move to staging. Only staged changes are included in the next commit. This lets you craft precise commits.

HEAD

A pointer to the current commit you are on. Usually points to the tip of your current branch. Detached HEAD means you are on a specific commit rather than a branch.

Essential Commands

CommandWhat it does
git initInitialise a new local repository in the current folder.
git clone <url>Download a remote repo to your machine.
git statusShow which files are staged, unstaged, or untracked.
git add <file>Stage a specific file for the next commit.
git add .Stage all changed files. Use carefully — can include files you did not mean to commit.
git commit -m "message"Save staged changes as a commit with a message.
git log --onelineCompact commit history — hash and message per line.
git diffShow unstaged changes. Add --staged for staged changes.
git push origin <branch>Upload your branch to the remote.
git pullFetch and merge changes from the remote into your current branch.
git fetchDownload remote changes without merging. Safe way to see what changed.

Branching & Merging

CommandWhat it does
git branchList all local branches. Current branch is marked with *.
git branch <name>Create a new branch (does not switch to it).
git checkout <branch>Switch to an existing branch.
git checkout -b <name>Create a new branch and switch to it immediately.
git merge <branch>Merge the named branch into your current branch.
git branch -d <name>Delete a branch (safe — won't delete if unmerged).
git stashTemporarily shelve uncommitted changes so you can switch branches cleanly.
git stash popRestore the most recently stashed changes.

Undoing Things

CommandWhat it does
git revert <hash>Create a new commit that undoes a previous one. Safe — does not rewrite history.
git reset --soft HEAD~1Undo the last commit but keep changes staged. Good for rewording a commit message.
git reset --hard HEAD~1Undo the last commit and discard all changes. Destructive — cannot be recovered easily.
git restore <file>Discard unstaged changes to a file, restoring it to the last commit state.
git restore --staged <file>Unstage a file (remove from staging area without losing changes).

Typical Workflow

# 1. Make sure you are on main and up to date
git checkout main
git pull

# 2. Create a feature branch
git checkout -b my-feature

# 3. Make changes, then stage and commit
git add specific-file.html
git commit -m "Add navigation bar to index page"

# 4. Push branch to remote and open a PR
git push origin my-feature

Tart

Tart is a macOS command-line tool for creating and running Apple Silicon virtual machines (macOS and Linux). It uses Apple's Virtualization framework — fast, lightweight, and native to Apple Silicon.

Concept

Tart VMs are identified by name. Images are downloaded from a registry (like OCI/Docker Hub but for VMs). You clone an image, give it a name, and run it. Each VM is isolated — changes inside the VM do not affect the host.

Commands

CommandWhat it does
tart listList all local VMs and their status (running/stopped).
tart pull <image>Download a VM image from the registry. Example: tart pull ghcr.io/cirruslabs/macos-sequoia-base:latest
tart clone <source> <name>Create a new VM named <name> from an existing image or local VM. Fast — uses copy-on-write.
tart run <name>Start and display a VM. Opens a graphical window by default.
tart run <name> --no-graphicsStart a VM in headless mode (no window). Useful for servers.
tart stop <name>Gracefully shut down a running VM.
tart delete <name>Permanently delete a VM and all its disk data.
tart ip <name>Get the IP address of a running VM (for SSH or web access).
tart get <name>Show details about a VM (CPU, memory, disk size).
tart set <name> --cpu 4 --memory 8192Configure a VM's CPU and memory (must be stopped first).

Typical Workflow

# Pull a macOS image
tart pull ghcr.io/cirruslabs/macos-sequoia-base:latest

# Clone it into a named VM
tart clone ghcr.io/cirruslabs/macos-sequoia-base:latest my-mac-vm

# Run it
tart run my-mac-vm

# In another terminal, get its IP
tart ip my-mac-vm

# SSH into a Linux VM (if SSH is enabled)
ssh admin@$(tart ip my-linux-vm)

# Stop and clean up
tart stop my-mac-vm
tart delete my-mac-vm

Useful Tips

Snapshots via clone: Clone a running VM before making risky changes. If things go wrong, delete the broken copy and clone again from the clean one.

Shared directories: Tart supports mounting host directories into the VM using --dir flag, so you can share files without SCP.

curl

curl is a command-line tool for making HTTP requests. Used here to interact with the Jamf Pro REST API — authenticating, retrieving data, and creating resources.

Core Flags

FlagWhat it does
-X <METHOD>Set the HTTP method: GET, POST, PUT, DELETE, PATCH.
-H "Header: Value"Add a request header. Use multiple -H flags for multiple headers.
-d '{"key":"value"}'Send a request body (for POST/PUT). Implies POST if no -X specified.
-u username:passwordBasic authentication shorthand.
-o <file>Write the response body to a file instead of printing it.
-sSilent mode — suppresses progress bar. Useful in scripts.
-iInclude response headers in output. Good for debugging.
-vVerbose — shows full request and response. Best for debugging.
| python3 -m json.toolPipe output to pretty-print JSON responses.

Jamf Pro API — Authentication

Jamf Pro uses Bearer token authentication for its modern REST API. First, exchange your credentials for a token, then use that token in subsequent requests.

# Step 1: Get a Bearer token
TOKEN=$(curl -s -X POST \
  "https://your-instance.jamfcloud.com/api/v1/auth/token" \
  -u "username:password" \
  -H "Accept: application/json" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['token'])")

echo $TOKEN

GET — Retrieve Data

# Get all computers
curl -s -X GET \
  "https://your-instance.jamfcloud.com/api/v1/computers-preview" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Accept: application/json" \
  | python3 -m json.tool

# Get a specific computer by ID
curl -s -X GET \
  "https://your-instance.jamfcloud.com/api/v1/computers-preview/1" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Accept: application/json"

POST — Create a Resource

# Create a new category (classic API — uses XML)
curl -s -X POST \
  "https://your-instance.jamfcloud.com/JSSResource/categories" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/xml" \
  -H "Accept: application/xml" \
  -d '<category><name>My New Category</name><priority>9</priority></category>'

# Create using JSON (modern API)
curl -s -X POST \
  "https://your-instance.jamfcloud.com/api/v1/categories" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "My New Category", "priority": 9}'

PUT — Update a Resource

# Update a category by ID
curl -s -X PUT \
  "https://your-instance.jamfcloud.com/api/v1/categories/5" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Renamed Category", "priority": 5}'

DELETE — Remove a Resource

# Delete a category by ID
curl -s -X DELETE \
  "https://your-instance.jamfcloud.com/api/v1/categories/5" \
  -H "Authorization: Bearer $TOKEN"

Invalidate Token (Clean Up)

curl -s -X POST \
  "https://your-instance.jamfcloud.com/api/v1/auth/invalidate-token" \
  -H "Authorization: Bearer $TOKEN"

Claude Code

Claude Code is Anthropic's official CLI for Claude — an AI assistant that works directly in your terminal, reads your project files, and helps you build software through conversation.

Starting & Stopping

CommandWhat it does
claudeStart an interactive Claude Code session in the current directory.
claude "do something"Run a one-shot task and exit (non-interactive).
Ctrl+CCancel the current operation or exit.

Slash Commands

CommandWhat it does
/initInitialise the project — creates CLAUDE.md with project context for future sessions.
/clearClear the conversation history and start fresh (context window reset).
/compactSummarise the current conversation to reduce context usage. Keeps working without losing history.
/helpShow all available slash commands and shortcuts.
/planEnter plan mode — Claude describes what it will do before taking any action.
/costShow how many tokens the current session has used.
/modelShow the current model being used.
/bugOpen a GitHub issue to report a Claude Code bug.

CLAUDE.md — Project Context File

Claude reads CLAUDE.md at the start of every session. It is your way of giving Claude persistent instructions about your project.

# CLAUDE.md

## Project Overview
Brief description of what this project is and does.

## Tech Stack
- Language / framework
- Key dependencies

## Repository Structure
| Folder | Purpose |
|--------|---------|
| src/   | Source code |
| tests/ | Test files |

## Conventions
- Use 2-space indentation
- Commit messages: imperative tense ("Add feature", not "Added feature")
- Never commit .env files

## Current State
What is the current focus or in-progress work?

Memory System

Claude Code supports a persistent memory directory for notes that survive across sessions.

FilePurpose
~/.claude/MEMORY.mdGlobal memory — loaded in every project. Good for personal preferences and recurring patterns.
.claude/memory/Project-level memory directory. Store topic-specific notes here.
COMPOUND.mdSession history file — decisions, tradeoffs, dead ends. Populated via /compound at end of session.

@ File References

Use @ to reference files directly in your prompt — Claude will read and use that file's content.

# Reference a file in your prompt
Review the code in @src/index.js and suggest improvements.

# Reference multiple files
Compare @day-3/site/planned/index.html with @day-3/site/one-shot/index.html

Hooks

Hooks are shell commands that run automatically in response to Claude Code events (e.g. before a file is written, after a tool is used). Configure them in settings to enforce rules automatically.

The Compound Engineering Loop

# 1. PLAN
/plan
"Describe what you want to build and ask Claude to plan it."

# 2. WORK
"Build it." (Claude reads, edits, creates files)

# 3. REVIEW
"Review what was built — open it in the browser, check the code."

# 4. COMPOUND
/compound
"Claude distils the session into COMPOUND.md for next time."
