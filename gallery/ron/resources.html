Host a Site on a Linux VM (LAN-accessible)

This guide walks through spinning up a Linux VM with Tart, installing nginx, and serving an HTML page that any device on your local network can open in a browser.

  1. Pull and create a Linux VM with Tart

    Pull a lightweight Linux image and clone it into a named VM.

    tart pull ghcr.io/cirruslabs/ubuntu:latest
tart clone ghcr.io/cirruslabs/ubuntu:latest my-web-vm
  2. Start the VM in headless mode

    No graphical window needed — we will SSH in.

    tart run my-web-vm --no-graphics &
  3. Get the VM's IP address

    Wait a few seconds for the VM to boot, then get its LAN IP.

    tart ip my-web-vm

    Note the IP — you will use it in the next step and to access the site from other devices.

  4. SSH into the VM

    Default credentials for Cirrus Labs Ubuntu images are usually admin / admin.

    ssh admin@$(tart ip my-web-vm)
  5. Install nginx

    Update package lists and install the web server.

    sudo apt update
sudo apt install -y nginx
  6. Start nginx and enable on boot 
    sudo systemctl start nginx
sudo systemctl enable nginx
sudo systemctl status nginx   # should show "active (running)"
  7. Create your HTML page

    The default nginx web root is /var/www/html/.

    sudo nano /var/www/html/index.html

    Paste your HTML, save with Ctrl+O, exit with Ctrl+X.

  8. Open it from any device on the same network

    On another Mac, phone, or device on the same Wi-Fi, open a browser and go to:

    http://<vm-ip-address>

    Your page should load.

  9. (Optional) Check the firewall

    If the page does not load, make sure port 80 is allowed.

    sudo ufw allow 80/tcp
sudo ufw allow 22/tcp   # keep SSH open
sudo ufw enable

LAN only: This setup is accessible on your local network only. To make it publicly accessible, see the "Useful Tools" tab for ngrok, or configure port forwarding on your router.

Expose an API from a Linux VM

Run a simple HTTP API on the VM using Python's built-in http.server module, then access it from other devices on the network. For real use, you would replace this with a proper framework like Flask or Express.

  1. SSH into your running VM 
    ssh admin@$(tart ip my-web-vm)
  2. Create a simple Python API

    Create a file called api.py:

    nano api.py

    Paste this content:

    from http.server import HTTPServer, BaseHTTPRequestHandler
import json

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == '/api/status':
            body = json.dumps({"status": "ok", "message": "API is running"})
            self.send_response(200)
            self.send_header('Content-Type', 'application/json')
            self.end_headers()
            self.wfile.write(body.encode())
        else:
            self.send_response(404)
            self.end_headers()

    def log_message(self, format, *args):
        print(f"[{self.address_string()}] {format % args}")

server = HTTPServer(('0.0.0.0', 8080), Handler)
print("API running on port 8080")
server.serve_forever()
  3. Run the API 
    python3 api.py
  4. Allow port 8080 through the firewall 
    # In another SSH session or after backgrounding the server
sudo ufw allow 8080/tcp
  5. Test it from your Mac 
    curl http://$(tart ip my-web-vm):8080/api/status

    You should get: {"status": "ok", "message": "API is running"}

  6. Access from any device on the network

    From a phone or other device on the same Wi-Fi, open:

    http://<vm-ip>:8080/api/status

Going Further — Real Frameworks

For a proper API, use a framework that handles routing, error handling, and middleware.

Python — Flask

pip install flask
# app.py
from flask import Flask, jsonify
app = Flask(__name__)

@app.route('/api/hello')
def hello():
    return jsonify({"message": "Hello"})

app.run(host='0.0.0.0', port=8080)

Node.js — Express

npm install express
// app.js
const express = require('express')
const app = express()

app.get('/api/hello', (req, res) => {
  res.json({ message: 'Hello' })
})

app.listen(8080, '0.0.0.0')

ngrok

Creates a public HTTPS tunnel to a locally-running server. Instantly share your VM-hosted site or API with anyone on the internet, no port forwarding required.

# Install (macOS)
brew install ngrok

# Sign up at ngrok.com and authenticate
ngrok config add-authtoken <your-token>

# Expose a local port
ngrok http 8080

# You get a public URL like:
# https://abc123.ngrok.io

curl

Command-line HTTP client. Test APIs, send webhooks, authenticate against Jamf Pro, debug requests. See the Cheat Sheet for Jamf Pro-specific examples.

# Quick test
curl https://httpbin.org/get

# POST JSON
curl -X POST https://httpbin.org/post \
  -H "Content-Type: application/json" \
  -d '{"key": "value"}'

# See response headers
curl -I https://example.com

python3 -m json.tool

Built-in JSON pretty-printer. Pipe curl output through it to make JSON readable in the terminal.

curl -s https://httpbin.org/get \
  | python3 -m json.tool

# Or use jq if installed (more powerful)
curl -s https://httpbin.org/get | jq '.'
curl -s https://httpbin.org/get | jq '.headers'

SSH

Secure remote shell. Connect to Linux VMs and remote servers to run commands as if you were sitting at the machine.

# Basic connection
ssh username@ip-address

# Copy a file to the remote machine
scp local-file.html admin@192.168.1.10:/var/www/html/

# Copy a file from remote to local
scp admin@192.168.1.10:/etc/nginx/nginx.conf ./

# Run a single command remotely
ssh admin@192.168.1.10 "sudo systemctl restart nginx"
