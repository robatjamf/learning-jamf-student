Deeper dive

What MDM really does

MDM (Mobile Device Management) lets one IT admin control thousands of devices from a single screen — no physical visits, no manual configuration on each machine.

📱
Install & remove apps silently
🔒
Enforce password & lock policies
📶
Configure Wi-Fi & VPN automatically
🗑
Remotely wipe a lost or stolen device
📊
See inventory of every managed device
⚙
Push settings & profiles at scale
75,000+ organisations use Jamf — including NASA, IBM, and thousands of schools. It's Apple-only and goes deeper than any cross-platform tool.
Why it mattered for your K-12 persona: An IT coordinator with 500 iPads, a tight budget, and teachers who aren't tech-savvy can't visit every device. MDM is what makes that job possible at all.

What I did with my Tart VM
I downloaded a configuration profile on my VM and managed to enroll it in my Jamf Pro instance. A VM is like a computer inside a computer — imagine your computer is a big house. The VM is one of those rooms: its own little house with its own rules.
API calls in Postman
I made a POST to create a new category and at first received a 401 — I wasn't authorised because I didn't have a token. Once I got the token it worked. I created a category for computers in my Jamf Pro instance.
What I learnt about webhooks
Webhooks are a way to send feedback when an event has occurred. They are automatic and do not really require human input. The payload looked like a bunch of information — hard to read unless you know the device IDs.

AnalogyCalling a restaurant to order food AnalogyA push notification arriving on your phone

The practical tell: If you clicked "Send" or typed curl — that was an API call, you started it. If data appeared on webhook.site without you doing anything — that was a webhook, Jamf started it.

The 401 Unauthorized you hit means the server understood you but needs proof of identity first. Bearer tokens solve this — authenticate once, get a token, attach it to every request like a wristband at an event.

Day 3

Building with AI —
The Compound Loop

Claude Code Plan Mode One-Shot vs Planned Compound Engineering Prompt Design

Built a full website twice in one day — once without planning, once with. The difference was significant. The biggest lesson wasn't about code: it was about how to work with AI.

My notes
After the One-Shot
The one-shot page was done well — it chose its own theme and all the information was included. I expected worse, like a bare HTML page, but it came out really well considering it had no context from me.
After the Planned Build
I spent the most time answering questions about what I wanted for the page. The planning process was fun — I felt like a part of the process and included in the major decision making. The planned page felt more personal and more of my style.
After the Review Step
The content matched my plan but the colour theme and layout was a bit different from what I anticipated. The agent covered things like what the goal of the page was, what I wanted to use it for — important stuff I was definitely not thinking about.
What surprised me about working with AI this way?
I was surprised at how relatively easy it is to build a website using AI. I also did not expect the website to be so well thought out, which I really appreciate. I enjoyed and learned a lot at the same time.
What I would tell a friend
Working with AI is all about the prompt. If your prompts are well structured and well thought out, your results are more likely to be what you want — instead of letting the agent blindly make decisions. It is not their fault when you get something you did not want due to being vague.
Deeper dive

One-shot vs Planned — and the Compound loop

⚡ One-shot
  • No context given
  • Agent makes all decisions
  • Fast — but generic
  • Hard to iterate on
✓ Planned
  • You define the brief
  • Agent asks questions first
  • Slower — but yours
  • Easy to build on

The Compound Engineering loop is the framework that makes the planned approach systematic:

01
Plan

Define before building. Ask questions. The plan IS the work.

02
Work

Execute within the plan. AI builds; you stay in control.

03
Review

Your eyes first. Use it. Then ask AI what it missed.

04
Compound

Distil decisions & lessons. Next session starts smarter.

Why it works: Senior engineers don't start coding immediately — they ask questions, write specs, draw diagrams. The Compound loop is that same practice, adapted for working with AI.

Day 2 Commands — Jamf Pro API
1. Get a bearer token
curl -s -u "jamfpro_api:eap.zog.neek26" \ -H "Content-Type: application/json" \ -X POST \ "https://projsadp.jamfcloud.com/api/v1/auth/token"
2. Save the token to a variable
TOKEN=$(curl -s -u "jamfpro_api:eap.zog.neek26" \ -H "Content-Type: application/json" \ -X POST \ "https://projsadp.jamfcloud.com/api/v1/auth/token" \ | jq -r '.token')
3. List all computers
curl -s \ -H "Authorization: Bearer $TOKEN" \ "https://projsadp.jamfcloud.com/api/v1/computers-inventory" \ | jq .
4. Update an Extension Attribute (triggers the webhook!)
curl -X PUT \ -H "Authorization: Bearer $TOKEN" \ -H "Content-Type: application/xml" \ "https://projsadp.jamfcloud.com/JSSResource/computers/id/YOUR_DEVICE_ID" \ -d '<computer> <extension_attributes> <extension_attribute> <id>1</id> <value>Amanda</value> </extension_attribute> </extension_attributes> </computer>'
